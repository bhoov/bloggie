<h2 id="start">Start in two commands</h2>

```sh
npx bloggie my-blog
cd my-blog && npm run dev        # http://localhost:4321/
```

The first command makes the blog in `my-blog/`, dates this post today, and installs its packages.
Add `--title "My blog" --author "Ada Lovelace"` to it to name the blog, or set these later in `src/site.js`.
You need Node 22 or later and git.

The second command opens the blog in your browser, and the page redraws each time you save a file.
It is a static site built with Astro: no server, no database, no account.
While `npm run dev` runs, you also get the slide editor and downloads made on click; `npm run build` checks every link and citation and builds the finished site into `dist/`.

<h2 id="story">A post is a story you can play with</h2>

A post mixes prose, equations, results and live demos.
A **figure** is a demo the reader drives in the page.
It waits for Play, so the page stays still until the reader asks; [](#fig-walk) is one.

<div id="fig-walk"><AttentionWalk client:visible={{ rootMargin: '600px' }} /></div>

A figure is an ordinary web component, in `src/figures/`: write it yourself, or describe what it should show and an agent builds it and checks it in a browser.
A demo that needs seconds of work waits behind a *Load demo* button, so a page never stalls.

Equations are typeset when the site builds, so they appear at once, and they are numbered and linked as in Quarto.
Each one can have braces that name its terms and a legend that names its symbols, as [](#eq-attention), the self-attention of a transformer, does:

<div class="eq-card">

$$
\label{eq-attention}
\state{Y} = \underbrace{\operatorname{softmax}\!\left(\frac{\given{X}\coupling{W_Q}\,(\given{X}\coupling{W_K})^\top}{\sqrt{d}}\right)}_{\mathclap{\note{attention weights}}}\;\underbrace{\given{X}\coupling{W_V}}_{\note{values}}
$$

<div class="eq-legend">

- **Shapes:** $N$ tokens of width $D$; queries, keys and values of width $d$.
- $\given{X} \in \mathbb{R}^{N \times D}$: **tokens**, one row per token.
- $\coupling{W_Q}, \coupling{W_K}, \coupling{W_V} \in \mathbb{R}^{D \times d}$: **projections** to queries, keys and values.
- $\state{Y} \in \mathbb{R}^{N \times d}$: **output**, each row a weighted average of the values.
- $\sqrt{d}$: keeps the scores near unit scale, so the softmax does not saturate.

</div>
</div>

Citations are managed for you.
Add a source once to `src/references.json`, and cite it by its key.
The post numbers each citation in order of first use, shows the source when the reader hovers over or taps the number, as <Cite key="vaswani2017">[Transformer]</Cite> does, and lists every source in the References at the end.
The build fails on a key that is not in the file.

Every section heading has a faint # that copies a link to it, so a reader can point a colleague at one paragraph.
The sections are listed in the margin of a wide window, with the one you are reading marked; in a narrow window, scroll up a little and a bar at the top names it and opens the list.
Press `t` to fold the list away or open it.

If you like, color each math symbol by its role, as the equation above does, and keep that color in every post and deck.
The roles and their colors are yours to name in `src/roles.js`; this blog's are:

<h2 id="slides">One story as blog and slides</h2>

A post can have a slide **deck**, a talk version of the post in a `slides.mdx` file beside it.
The deck runs the same live figures, so a demo you build once works on the page and on the projector.
Once you are happy with the story of your post, ask an AI agent to generate the deck for you.
Press `s` on a post to open its deck, as on [this post's deck](slides/).

</figcaption>

| Key | What it does |

**Ask an agent for the deck.**
The `bloggie-slides` skill ships with the blog, in `.agents/skills/bloggie-slides/`, so any coding agent can read it.
It turns a post into slides with one idea each, text large enough for the back of the room, and full-slide demos.
It checks every slide in a browser, then tells you where the post's story was hard to follow.
You can also write a deck yourself: `## Title` starts a slide, and the source of this post's deck is at the end of this section.

**Fine-tune it with the mouse.**
Under `npm run dev`, press `e` on a deck to turn on the **slide editor**.
Drag, resize and align blocks, change fonts and colors, and edit text in place.
Double-click words to bold or color only those words, and use the column of slides on the left to duplicate or delete a slide.
The keys follow Figma's.
Each change goes straight into `slides.mdx`, so the deck stays a text file, and your edits and an agent's mix freely.

When the argument changes in one, ask the agent to carry the change to the other: "Update the deck for the changes to the post."
It keeps the layout you set with the editor.

<h2 id="files">Everything is a plain text file</h2>

A post is one folder, and every file in it is text you can open in any editor:

```
src/pages/posts/<slug>/
  index.mdx       the post: Markdown, math and figure tags
  slides.mdx      its deck (optional)
  data/  media/   the numbers and pictures it shows
```

To start a post, copy this post's folder to `src/pages/posts/<slug>/` and change its title and date at the top of `index.mdx`; the home page lists every post, newest first.
To take this example off your site, rename its folder to `_how-this-blog-works`: a folder whose name starts with `_` is not published.
Front matter `tags: [wip]` marks a post in progress on the home page, and `tags: [archived]` hides it until the reader asks for it.

Write one sentence per line.
Your editor wraps long lines, and a diff then shows which sentence changed.
Most edits are a line or two, as [the table below](#tbl-edits) shows.

<figure id="tbl-edits">
<figcaption>

**What to write for each element of a post and its deck.**

</figcaption>

| To add | Write |
| --- | --- |
| Section | `<h2 id="setup">Setup</h2>` |
| Equation | `$$ … $$`, with `\label{eq-name}` to number it |
| Link to it | `[](#eq-name)`, shown as "Eq. (1)" |
| Symbol color (optional) | `$\given{X}$`, one macro per role in `src/roles.js` |
| Citation | `<Cite key="vaswani2017">[Transformer]</Cite>` |
| Figure | its tag, such as `<AttentionWalk client:visible />` |
| Slide | `## Title` in `slides.mdx` |
| Demo slide | `## [demo] Title`, then a figure's tag |
| Equation slide | `## [equation] Title`, then the equation and its symbols |

</figure>

To change something you see, find it with the mouse: under `npm run dev`, Cmd+Shift+click it (Ctrl+Shift+click on Linux and Windows).
VS Code opens the file that wrote it at the word you clicked: the `.mdx` for text, equations and code, the `.svelte` file for a part of a figure.
This also works when the dev server runs on another machine that VS Code reaches over SSH.

<h2 id="style">One style, written down for your agent</h2>

`AGENTS.md`, at the top of the repository, is the blog's style guide and the manual for any coding agent (Claude Code and Codex both read it).
It says how a post is written, how a figure is built and checked, and how a deck looks.
Some of its rules are one sentence per line, an example beside each idea, and legends that read like slides.
Add your own rules, and every agent follows them in every post and deck.
The build enforces the mechanical ones: a broken link within a page or an unknown citation stops `npm run build`.

You write the argument; the agent builds and checks what it needs.
For example:

> Draft a post in `src/pages/posts/<slug>/` from these notes: …
>
> Build a figure for the post that shows …
>
> Read the post as a first-time reader in a browser, use every control, and list what is unclear.
>
> Make slides for the post with the bloggie-slides skill.

<h2 id="downloads">Download for offline distribution</h2>

The <svg viewBox="0 0 16 16" width="15" height="15" aria-label="download" style="vertical-align: -2px"><path d="M8 2v8m-3.5-3.5L8 10l3.5-3.5M3 13h10" fill="none" stroke="currentColor" stroke-width="1.6" stroke-linecap="round" stroke-linejoin="round" /></svg> in each post's byline downloads the post as one file, and the menu beside it offers two kinds:

- **Interactive page.**
  Styles, fonts, images, video, figures and the deck, all inside one HTML file.
  It opens from disk with a double click and needs no internet, so you can present from a laptop offline, or send the post by email.
- **For agents.**
  The post as text for a language model, with math as MathML and its TeX source.
  Each figure becomes a description with traces from its own numbers, and the figures' source code is appended.
  Give it to another agent as reading material.

<h2 id="publish">Publish</h2>

Push the blog to a GitHub repository; each push to `main` builds the site and publishes it to GitHub Pages.
Once, in the repository's Settings → Pages, set the source to GitHub Actions.
The site's address comes from GitHub Pages when it builds, so a downloaded post links back to it.
